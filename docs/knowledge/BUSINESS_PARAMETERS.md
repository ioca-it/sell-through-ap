# Catálogo oficial de parámetros de negocio y operación

## Propósito y alcance

Este documento inventaría los parámetros, constantes, textos y reglas observables de `sell-through-ap` al cierre de Prompt 019. Es la fuente oficial para diseñar el futuro Configuration Center y cualquier migración de parámetros, sin cambiar el comportamiento vigente.

El catálogo se construyó únicamente desde el JSON institucional, el estado React, Application Service, Domain, Repository y Local Provider autorizados. No define entidades, campos, permisos ni mapeos Dataverse. Como no existe esquema aprobado, todas las filas mantienen `Pendiente de definición` en la columna Dataverse.

No se catalogan como parámetros los registros de muestra `maestroSample` e `inventarioSample`, las entradas pegadas de Maestro/Inventario ni los resultados calculados por SKU: son datos, fuentes o salidas. Los colores CSS dispersos de maquetación tampoco son parámetros de negocio; sí se registran las paletas nombradas que participan en interpretaciones de Tier, categoría y rotación.

## Criterio de clasificación

- **Parámetro configurable:** valor de sesión o dato institucional que puede variar sin redefinir una fórmula. `Editable en Configuration Center` distingue si corresponde centralizarlo o si debe permanecer como dato de sesión.
- **Constante técnica:** contrato de presentación, exportación, integración o infraestructura que no es una política comercial.
- **Texto de UI:** contenido narrativo o explicativo; no debe alterar cálculos.
- **Regla fija:** fórmula, precedencia, condición o fallback que requiere aprobación funcional antes de parametrizarse.
- **Valor derivado:** valor calculado desde datos o reloj; nunca debe editarse como parámetro.

Los conteos de configurable/no configurable usan la columna `Estado`: 82 filas son `Parámetro configurable`; las otras 78 son no configurables. La indicación `Hardcode actual` identifica un literal o contrato embebido en JavaScript/JSX, aunque se recomiende centralizarlo después.

## Riesgos y pendientes para Configuration Center

- Buckets EOL tienen definición visible en JSON, pero sus límites efectivos y el orden se resuelven mediante literales/posiciones en Domain. Deben unificarse antes de habilitar edición para evitar divergencias.
- El gate global de fase de 90 días duplica los mínimos F0; una tabla con un mínimo menor no surtiría efecto completo.
- El fallback `4.33` está duplicado entre Domain, UI y el período Mensual del JSON.
- Application Service exige presencia de cinco claves, pero no valida tipos, finitud ni rangos; los límites actuales dependen del formulario.
- `fechaCorte` es contexto de sesión/exportación, mientras EOL usa el reloj del navegador.
- Textos narrativos, versiones, nombres de archivo y referencias 20/80 aparecen duplicados entre JSON, JSX y exportaciones.
- No existe modelo de permisos, persistencia, asincronía, autenticación ni esquema Dataverse aprobado.

## Estrategia de reversión

Este cambio es documental. Para revertir Prompt 019 se deben retirar este archivo y las entradas documentales asociadas mediante un cambio Git explícito, sin modificar `src`, `package.json`, dependencias, reglas ni defaults.
